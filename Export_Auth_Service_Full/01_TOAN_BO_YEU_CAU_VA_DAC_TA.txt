I. TỔNG QUAN YÊU CẦU NGHỆP VỤ (BUSINESS REQUIREMENTS)
--------------------------------------------------------------------------------
1. Quản lý Tài khoản & Phân quyền (RBAC):
   - Hệ thống có 4 vai trò chính:
     + Admin: Quản trị viên hệ thống (quyền cao nhất)
     + Secretary: Thư ký phòng ban / đơn vị
     + SecretaryDirector: Thư ký Ban Giám Đốc (quyền phát hành công văn & nhận mail thông báo)
     + Employee: Nhân viên thông thường
   - Đăng nhập (Login):
     + Nhận request { username, password }
     + Mã hóa mật khẩu bằng BCrypt
     + Trả về JSON envelope: { success: true, data: { accessToken, refreshToken, expiresIn: 3600, user: { id, fullName, role, departmentId } } }

2. Bảo mật Token & Vòng đời Refresh Token (Token Rotation):
   - AccessToken: HMAC-SHA256 JWT, thời hạn 1 giờ, chứa Claims: sub, fullName, departmentId, role.
   - RefreshToken: Chuỗi ngẫu nhiên 64-bytes Base64, thời hạn 7 ngày, lưu bảng auth.RefreshTokens.
   - Cơ chế Token Rotation (Single-Use Enforcement):
     + Khi client gửi request Refresh Token hợp lệ (/api/auth/refresh), hệ thống thu hồi Refresh Token cũ (gán RevokedAt = DateTime.UtcNow) và cấp cặp Token mới.
     + Nếu Refresh Token cũ (đã RevokedAt != null) tiếp tục được gửi lại, hệ thống BẮT BUỘC từ chối (401 Unauthorized) để chống Replay Attack.

3. Tra cứu Người dùng theo Role (Inter-Service Integration):
   - Endpoint: GET /api/users?role={role}
   - Cho phép các microservice khác (như document-service) query email của Thư ký BGD (SecretaryDirector) để tự động gửi mail notification khi phát hành công văn.
