4. THUẬT TOÁN & KĨ THUẬT CỐT LÕI ĐÃ TRIỂN KHAI

4.1. Sinh số công văn tự động — Thread-safe (Concurrency-safe)

Vấn đề: Khi nhiều người tạo công văn cùng lúc, số công văn có thể bị trùng (race condition).

Giải pháp: Sử dụng SQL Transaction với mức cách ly Serializable, kết hợp khóa dòng counter bằng SELECT ... WITH (UPDLOCK, HOLDLOCK) trên bảng DocumentNumberCounters, đảm bảo chỉ một request được đọc-và-tăng counter tại một thời điểm.

Định dạng số hiệu: CV-DEN-2026-0001 (Công văn đến), CV-DI-2026-0001 (Công văn đi), CV-NB-2026-0001 (Nội bộ). Counter tự động reset khi sang năm mới (theo cặp DocType + Year).

Fallback: Có cơ chế LINQ query dự phòng cho SQLite khi test local không có SQL Server.

4.2. Workflow trạng thái — State Machine + Audit Trail

Luồng trạng thái hợp lệ: Draft → Reviewed → Distributed (cho phép bỏ qua bước Reviewed, chuyển thẳng Draft → Distributed). Hệ thống chặn mọi thao tác chuyển ngược trạng thái (ví dụ: Distributed → Draft sẽ trả về 400 Bad Request).

Mỗi lần đổi trạng thái, hệ thống tự động ghi một bản ghi nhật ký vào bảng DocumentStatusHistory, lưu trữ đầy đủ thông tin: OldStatus, NewStatus, ChangedByUserId, ChangedAt, và Note.

Khi chuyển sang trạng thái Distributed, hệ thống tự động cập nhật DistributedAt = UTC Now và gửi thông báo email phát hành qua NotificationService.

4.3. Phân quyền truy cập — RBAC + ABAC

Vai trò Quyền truy cập công văn
Admin / SecretaryDirector ✔ Xem TẤT CẢ công văn
User thường (Staff / SecretaryDept) Chỉ xem nếu: (1) Phòng ban mình là phòng gửi, HOẶC (2) Phòng ban mình được phân quyền trong DocumentDepartmentAccess, HOẶC (3) Công văn đã phát hành (Distributed)

4.4. Soft Delete (Xóa mềm)

Hệ thống chỉ cho phép xóa công văn khi ở trạng thái Draft. Thay vì xóa cứng khỏi database, hệ thống đánh dấu IsDeleted = true và ghi nhận DeletedAt = UTC Now, đảm bảo dữ liệu vẫn được lưu giữ cho mục đích kiểm toán. Sử dụng EF Core Global Query Filter (HasQueryFilter(d => !d.IsDeleted)) để tự động ẩn công văn đã xóa khỏi mọi truy vấn mà không cần viết điều kiện lọc thủ công.

4.5. Xử lý lỗi tập trung — GlobalExceptionHandler

Lớp GlobalExceptionHandler.cs sử dụng interface IExceptionHandler (.NET 10) bắt toàn bộ ngoại lệ runtime và chuẩn hóa phản hồi JSON theo format: { success: false, message: "...", errors: [] }. Tự động ánh xạ các loại Exception phổ biến: KeyNotFoundException → 404 Not Found, InvalidOperationException và ArgumentException → 400 Bad Request, UnauthorizedAccessException → 403 Forbidden, và các exception không xác định → 500 Internal Server Error.

4.6. Giao tiếp liên Service — Typed HttpClient

Client Interface Service đích Mục đích
IPartnerServiceClient partner-service Truy vấn thông tin đối tác gửi/nhận công văn
IFilesServiceClient files-service Truy vấn metadata file đính kèm
INotificationServiceClient notification-service Gửi email thông báo khi công văn được phát hành

Cơ chế Graceful Error Handling: nếu service phụ thuộc offline, document-service vẫn hoạt động bình thường, không bị crash.

10 DELETE /api/documents/{id}/attachments/{attId} Xóa tệp đính kèm khỏi công văn Path: Guid id, Guid attachmentId
11 DELETE /api/documents/{id} Xóa công văn (Soft Delete — chỉ khi Draft) Path: Guid id
